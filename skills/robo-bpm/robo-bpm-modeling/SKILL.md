# 업무 프로세스 모델링 규칙

이 규칙은 **문서에 있는 것만** 모델로 옮기기 위한 것이다. 문서에 근거가 없으면 만들지 않는다.
그림이 깔끔한 프로세스는 그리기 전에 **모델이 깔끔하다** — 분기는 진짜 갈림길에만, 갈래는 서로 다른 곳으로,
결말마다 끝을 따로 둔다.

## 1. 작업(task)

1. 작업은 **한 역할이 한 의미 단위로 하는 일**이다. 다음에서 작업을 나눈다:
   역할이 바뀔 때 · 다른 사람에게 넘길 때(인계) · 승인·대기 지점.
   같은 역할이 이어서 하는 잔일은 하나로 합친다.
2. 이름은 짧은 동사구(예: "신청서 접수", "잔여 휴가 확인", "결재 처리").
3. 모든 작업에 **수행 역할(actor)** 을 붙인다. 역할은 문서의 역할·부서·시스템 이름을 그대로 쓴다.
4. 작업 종류: 사람이 하면 `human`, 시스템이 자동으로 하면 `system`.
5. "통보·완료·마감·소멸" 같은 **끝내는 작업은 첫 작업이 될 수 없다.** 첫 작업은 흐름을 시작하는 일(요청·접수·대상 확인 등)이다.
6. 작업은 **주 흐름 순서대로** 나열한다. 이 순서가 분기가 없는 구간의 연결이 된다.

## 2. 분기(gateway)

1. 분기는 **문서에 실제로 갈리는 근거가 있을 때만** 만든다: "~에 따라", "~인 경우", "~면 …, 아니면 …", "판단", "결정", "여부".
   근거가 없으면 **선형으로 둔다.** 분기를 지어내지 않는다.
2. 분기 이름은 **판단 지점의 이름**이다. 조건 문구가 아니다. "~인지 여부" 는 `<주제> 여부 판단` 으로.
   예: "마감 상태 판단", "증빙 필요 여부 판단".
3. 분기는 **바로 앞 작업(after_task)** 이 반드시 있다.
4. 갈래는 **2개 이상**이고, 각 갈래의 조건은 **서로 의미가 다르다.**
   "조건1/분기1/case1" 금지. 두 갈래면 `<주제>인 경우 / <주제>이 아닌 경우` 처럼 짝을 맞춘다.
5. **갈래들은 서로 다른 곳으로 간다.** 두 조건이 같은 다음 작업으로 가면 그것은 분기가 아니다 — 분기를 만들지 말고 선형으로 둔다.
6. 각 갈래는 다음 중 **하나**로 간다:
   - `to_task`: 그 갈래가 이어지는 **작업 이름**(추출한 작업 이름과 정확히 같아야 한다)
   - `to_end`: 그 갈래에서 **프로세스가 끝나면** 그 결말 이름(예: "반려 종료", "발주 없음", "이미 마감됨")
   맨 끝 작업으로 건너뛰는 갈래를 만들지 말고, 그 갈래에서 실제로 하는 일(작업)로 보내거나 `to_end` 로 끝낸다.
7. **갈래의 대상은 그 조건에서 실제로 다음에 하는 일**이다. 예: "이미 마감됨" 이면 다음 일은 "마감 해제" 다 —
   맨 끝 "전 사원 마감 배치" 가 아니다. 대상을 고르기 전에 문서에서 그 조건 다음 문장을 다시 읽는다.
8. 분기의 역할(actor)은 **판단하는 역할**이다(보통 바로 앞 작업의 역할).
9. 종류: 하나만 고르면 `exclusive`, 동시에 모두 가면 `parallel`(조건 없음), 여러 개를 고를 수 있으면 `inclusive`.

## 3. 검사 단계와 되돌림(loop)

1. **검사·확인 단계**(기한 확인, 증빙 확인, 중복 확인, 한도 확인 …)는 기본이 **작업**이다.
   그 검사에서 **문서가 다른 흐름을 정의할 때만** 뒤에 분기를 둔다.
2. 검사에 걸려 **신청이 반려되고 끝나는** 경우: 처음 작업으로 되돌리지 말고 `to_end` 로 끝낸다
   (예: "중복 신청 반려", "한도 초과 반려"). 같은 결말이면 같은 끝 이름을 쓴다.
3. 되돌아가는 갈래(예: 반려 → 다시 신청)는 문서에 **"다시", "재", "보완 후 재제출"** 같은 근거가 있을 때만.
4. 되돌림 대상은 다시 하는 그 작업이다. 근거 없이 처음 작업으로 돌리지 않는다.
5. 분기 이름에 업무 규칙 문장을 그대로 쓰지 않는다("현재 대기 단계의 결재자만 처리할 수 있다 여부 판단" ✗ → "결재 결과 판단" ✓).
   규칙 문장은 작업 설명에 둔다.

## 4. 시작과 끝

1. 시작은 하나 — 첫 작업으로 이어진다.
2. **끝은 결말마다 따로**: 정상 완료, 반려 종료, 대상 없음처럼 결말이 다르면 끝도 다르다(`to_end` 의 결말 이름).
3. 모든 작업과 분기는 **다음이 있다** — 다음 작업, 다른 분기, 또는 끝. 갈 곳 없이 남는 것(고아)이 없다.
4. 모든 작업은 **시작에서 닿는다** — 들어오는 흐름이 없는 작업이 없다. 순서상 앞 작업 뒤에 오지 않는 작업이면 어느 분기의 어떤 갈래에서 오는지 밝힌다.

## 5. 내기 전에 스스로 점검

- [ ] 분기마다 문서 근거가 있다
- [ ] 분기마다 갈래 2개 이상, 조건이 서로 다르다, 대상이 서로 다르다
- [ ] 갈래 대상이 "그 조건에서 다음에 하는 일" 이다(맨 끝으로 건너뛰지 않았다)
- [ ] 들어오는 흐름이 없는 작업이 없다(첫 작업 빼고)
- [ ] 끝내는 작업이 첫 작업이 아니다
- [ ] 결말이 다르면 끝 이름이 다르다
- [ ] 작업·분기 이름이 추출 목록과 정확히 일치한다
