## 3. 저장소·브랜치 지형

핀은 전부 `uengine-oss` 소유다. 이름은 두 가지뿐이다.

| pin | 브랜치 | 저장소 |
|---|---|---|
| architect | `enterprise-custom-p` | uengine-oss/robo-architect |
| (workspace 자신) | `enterprise-custom-p` | uengine-oss/robo-workspace |
| antlr | `enterprise-electron` | uengine-oss/antlr-code-parser |
| ontological | `main` | **uengine-oss/ontological-db-enterprise-custom** |
| gateway | `main` | uengine-oss/robo-api-gateway |
| analyzer · catalog · fabric · frontend | (gitlink SHA) | 각 저장소의 `enterprise-electron` |
| open-pencil | (gitlink SHA) | open-pencil 의 `enterprise-electron` |

- `enterprise-custom-p` = 원본 기능과 납품 구성을 가르는 줄기. 양쪽 저장소가 짝.
- `enterprise-electron` = **Electron 납품본을 띄우기 위해 존재하는 브랜치**.
  커밋을 옮긴 적은 없고 이름만 통일했다.
- 서브모듈은 `.gitmodules` 의 `branch = main` 이 **장식**이다 — 실제 고정은
  부모가 기록한 gitlink SHA 다. 다만 그 SHA 가 도달 가능하도록 브랜치는 남아야 한다.

### ontological-db 이전 (오늘)

개인 fork(`seongwonyang/ontological-db`)에 **그래프 저장소 본체**가 있었다.
상류로 돌리는 길은 막혀 있었다 — `uengine-oss/ontological-db` 에 푸시 권한이 없고
(403), 상류 PR #2 는 3주 리뷰 없이 닫혔다. 그래서 조직 소유의 별도 저장소
`uengine-oss/ontological-db-enterprise-custom` 으로 옮기고 그 `main` 을 가리킨다.

**하드 포크다.** 상류가 고치는 것이 자동으로 오지 않는다. 로컬 체크아웃에
`upstream` 리모트를 남겨 뒀다. 상류는 2026-08-24 이후 멈춰 있어 당장은 비용이 없다.

## 6. 아직 확인 안 된 것 / 미해결

### 납품본은 아직 없다

지금 구운 것은 `releaseChannel: internal-test`, `authEnforced: false` 다.
`robo-workspace/.env` 가 `AUTH_ENFORCE=false` + `ROBO_RELEASE_CHANNEL=internal-test`
라 납품 관문을 우회했다. 전달본은 `AUTH_ENFORCE=true` · `AUTH_PROVIDER`(swp/posco)
· `AUTH_JWT_SECRET` 을 채우고 다시 구워야 한다. **그 값들은 사람이 정한다.**

### `/api/figma-binding/failures` 가 백엔드를 통째로 멈춘다

싱크 실패가 **1건이라도** 있으면 History 탭·실패 패널을 여는 순간 앱 전체가
정지한다. 두 겹이다.

- `repository.py` 의 `OPTIONAL MATCH (u:UI {id: uid})<-[*1..30]-(c0:Command)` —
  관계 타입 제한 없는 30홉 역방향 경로를 실패 UI 마다 돈다. 끝나지 않는다.
- `router.py` 의 `get_failures` 가 `async def` 인데 동기 함수를 스레드풀 없이
  직접 부른다 — uvicorn 이벤트 루프가 막혀 **한 요청이 앱 전체를 세운다.**

실패가 0건일 때는 조기 반환해서 드러나지 않았다. 운영 문서에 "열지 말라"고
적었지만 그건 회피지 수정이 아니다. **사용자가 실제로 밟을 가능성이 가장 높다.**

### 룰 매핑이 비결정적이다

같은 입력·같은 코드·같은 모델인데 **22/68 → 17/68**(룰 붙은 task 10 → 9).
에이전트 탐색이라 그렇다. 미배정 51건 중 **검토 큐로 올라온 것은 0건** —
임계값 아래는 사람에게 묻지 않고 버려진다.

하류로 그대로 간다: UserStory 30개 중 룰 출처를 가진 것이 11개뿐이라, 나머지
19개는 출처 패널이 비어 있다(백엔드는 정상).

### BPMN 게이트웨이 추출도 흔들린다

같은 문서 세 번 호출에 gateway 1 / 1 / 0, flow 21 / 16 / 17. `temperature=0`
인데도 그렇다. 신·구 이미지 A/B 로 **이미지 탓이 아님**은 확인했다.

폴백이 같은 문서에서 gateway 5 를 냈지만, 그쪽이 "…확인" 단계를 다이아몬드로
만든 것으로 보인다 — facade 프롬프트는 그것을 명시적으로 금지한다. **개수가
품질은 아니다.**

### `source_pdf_name` 오기 (폴백 경로 한정)

네이티브 폴백은 프로세스 3개의 출처를 전부 첫 PDF 로 찍는다(두 판 연속 재현).
