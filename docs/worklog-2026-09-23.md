  부모가 기록한 gitlink SHA 다. 다만 그 SHA 가 도달 가능하도록 브랜치는 남아야 한다.

## 9. 오후 추가 작업 (2026-09-23)

### 설치본을 감사해 비밀 유출을 찾았다

설치본의 `config/*.env` 를 전수로 훑으니 **같은 OpenAI 키가 5개 파일 7개
이름으로** 들어 있었다. `release-environment.json` 의 `credentialNames` 를
제외 목록이라고 읽은 것이 틀렸다 — 그건 **"진짜 값을 넣어라"는 검증 목록**
이었고, 포장 단계는 `.env` 를 그대로 베꼈다.

고쳤다 — 릴리스가 비밀을 빼고 **이름만** 매니페스트에 싣는다. 값은 설치한
사람이 환경변수로 넣고 compose 가 컨테이너로 넘긴다. 없으면 앱이 기동에서
이름을 대고 멈춘다(`runtime.credentials_missing`). 자세한 것은 핸드오프 §6-B.

`PDF2BPMN_FACADE_KEY` / `FACADE_API_KEY` 이름 불일치도 같이 없앴다 — 이제
정할 값은 하나다.

### `/failures` 정지를 고쳤다

같은 탐색을 이미 최적화해 둔 `storyboard_resolver` 가 옆에 있었는데
`fetch_classifier_view` 가 그것을 인라인으로 다시 짰다(그것도 관계 타입 제한
없이). 거기에 `WITH uid, c LIMIT 1` 이 스트림 전체에 걸려 **"보관됨" 판정을
받을 수 있는 UI 가 최대 한 건**이던 조용한 오답까지 있었다.

resolver 에 위임하고, 라우터의 `async def` 를 떼어 threadpool 로 보냈다.
ContextVar 가 워커 스레드로 따라가는지는 **번들 런타임으로 실측**했다 —
안 따라갔다면 다른 프로젝트의 실패 목록을 보여줬을 것이다. 핸드오프 §6-C.

### 릴리스 관문 테스트가 5일째 빨간 채였다

`tests/environment-contract.ps1` 은 **내 변경 이전부터** 실패하고 있었다.
기대값을 숫자로 박아둔 자리 세 곳이 현실과 어긋나 있었다(오류 개수 2, 픽스처
`AUTH_ENFORCE` 누락, 스키마 3). 개수 검사는 이름 검사로, 스키마는 앱 상수를
읽도록 바꿨다. 지금은 통과한다. **CI 에 걸려 있지 않으므로 또 썩을 수 있다.**

### 아직 구워지지 않았다 — 중요

지금 `_releases/` 의 설치 파일은 **오늘 고친 것을 하나도 담고 있지 않다.**

```text
릴리스가 쓴 SHA    workspace 9a12dc2 · architect 00eeb56
그 뒤 고침         ef6c14a  스테이징 잔재 제거
                   d11ce18  아카이브 안내 문구
                   (오후)   비밀 미포장 + /failures
```

증거는 설치본 안에 있다 — `resources/runtime/` 에 `compose.yml.bak` 과
`runtime-manifest.json.bak` 이 **그대로 있다.** `ef6c14a` 가 없애려던 파일이다.

**"고쳤다" 를 "산출물이 그렇다" 로 읽지 마라.** 이 문서를 쓰는 이유 중
하나가 그것이다.
