# Feature Specification: 선점 잠금을 접속에 묶는다 — 두 편집 경로 공통

**Feature Branch**: `enterprise-custom-p` (전용 브랜치를 따지 않는다 — 납품 브랜치에서 이어 간다)
**Spec Dir**: `specs/057-presence-bound-element-lock`
**사용자 매뉴얼**: [manual/manual.md](manual/manual.md) (+ `manual.docx`) — 화면 캡처는 Playwright 로 생성
**Created**: 2026-09-17
**Status**: 구현·검증 완료 (2026-09-17) — US1~US5 화면에서 통과, 결함 주입 6종 확인

**Input**: 동시편집에서 **Inspector 직접 편집**과 **AI 챗 편집** 두 경로가 같은 선점을
공유해야 한다. 지금은 선점에 **60초 고정 TTL** 이 걸려 있는데, 그 벽이 활성 편집자의
잠금을 걷어 간다. 반대로 선점한 채 **브라우저를 끄거나 앱이 종료되면** 잠금이 남는
갈래가 있다.

## Problem

`app_element_locks.refreshed_at` 이 `now() - 60초` 보다 오래되면 남이 집어갈 수 있다.
그 60초를 갱신하는 것은 SSE 스트림뿐이다(`refresh_locks`, 2초 주기).

```
사람은 편집 중인데 스트림만 60초 넘게 멎으면   → 잠금이 걷힌다 (절전·재연결 백오프 최대 30초·프록시)
사람이 떠났는데 스트림 정리가 안 돌면          → 최대 60초 동안 아무도 못 고친다
접속자는 15초면 사라지는데(PRESENCE_TTL)        → 잠금만 60초를 더 산다. 두 수명이 어긋난다
```

**시계로 재는 것이 틀렸다.** 재야 하는 것은 "몇 초가 지났나"가 아니라 **"그 사람이
아직 붙어 있나"** 다. `app_project_presence` 가 이미 그 사실을 들고 있는데 잠금이 그것을
안 본다.

그리고 두 편집 경로는 지금 같은 잠금을 쓰지만 **한 경로만 화면에서 검증됐다.**
직접 편집은 여덟 종류를 그래프까지 확인했고(done-v2 §56), AI 챗은 `/api/chat/confirm`
까지만 쟀다 — **프롬프트 입력 → LLM 초안 → 승인 클릭**은 한 번도 안 지났다.

## User Scenarios

### US1 — 붙어 있는 동안에는 선점이 안 풀린다 (P1)

한 요소를 열어 두고 60초보다 오래 고친다. 스트림이 붙어 있는 한 잠금은 유지된다.
고정 만료 시각이 없다.

**Acceptance**
1. **Given** alice 가 요소를 잡고 Inspector 를 열어 두었고, **When** 90초가 지나도
   스트림이 살아 있으면, **Then** 잠금은 alice 의 것이고 bob 은 못 집는다.
2. **Given** 같은 상태에서, **When** alice 가 저장하면, **Then** 409 없이 그래프에 들어간다.

### US2 — 창을 닫거나 앱이 죽으면 선점이 남지 않는다 (P1)

**Acceptance**
1. **Given** alice 가 잡고 있고, **When** 창을 정상적으로 닫으면, **Then** 잠금은
   **즉시** 사라진다(스트림 종료 경로).
2. **Given** alice 가 잡고 있고, **When** 브라우저 프로세스를 강제 종료하면,
   **Then** `LOCK_ABSENT_GRACE` 안에 사라지고 bob 이 집을 수 있다.
3. **Given** 잠금이 남아 있는 상태에서, **When** 백엔드가 재시작되면, **Then** 기동
   시 정리되어 유령 잠금이 0 이다.

### US3 — 끊기면 화면이 말한다 (P2)

**Acceptance**
1. **Given** alice 가 잡고 있고, **When** 스트림이 끊기면, **Then** 화면에 연결이
   끊겼다는 것과 **잠금을 잃을 수 있다는 것**이 뜬다. 조용히 계속 편집하게 두지 않는다.
2. **Given** 그 상태에서, **When** 스트림이 돌아오고 아무도 안 집어갔으면,
   **Then** 자동으로 다시 집고 배너가 사라지며 계속 고칠 수 있다.
3. **Given** 끊긴 사이 bob 이 집어갔으면, **When** alice 가 돌아오면, **Then**
   **누가 가져갔는지**가 뜨고 입력칸이 잠긴다.

### US4 — 두 편집 경로가 같은 선점을 공유한다 (P1)

같은 요소를 Inspector 로도, AI 챗으로도 고친다. 둘은 같은 잠금을 본다.

**Acceptance**
1. **Given** bob 이 요소를 잡고 있고, **When** alice 가 **AI 챗에서 그 요소를 고르면**,
   **Then** 배너가 뜨고 프롬프트 입력칸이 잠긴다. LLM 을 부르기 전에 막힌다.
2. **Given** alice 가 Inspector 로 잡고 있고, **When** 같은 창에서 챗으로 전환하면,
   **Then** 잠금은 alice 의 것으로 유지된다(패널 전환 ≠ 손 뗌).
3. **Given** alice 가 잡고 있고, **When** alice 가 챗에서 **프롬프트를 쳐서 LLM 초안을
   받고 승인을 누르면**, **Then** 그래프가 바뀌고 bob 의 창에 그 변경이 나타난다.

### US5 — 어느 경로로 고쳤든 상대 창에 나타난다 (P2)

**Acceptance**
1. **Given** 두 창이 같은 프로젝트를 열고 있고, **When** alice 가 Inspector 로 저장하면,
   **Then** bob 의 목록·내용이 새로고침 없이 바뀐다.
2. **Given** 같은 상태에서, **When** alice 가 AI 챗 승인으로 바꾸면, **Then** 같은 일이
   일어난다.

## Requirements

- **FR-001** 잠금의 수명은 **보유자의 접속(presence)** 으로 정한다. 고정 TTL 을 두지 않는다.
  잠금은 보유자의 `last_seen` 이 `now() - LOCK_ABSENT_GRACE` 보다 최근일 때만 살아 있다.
- **FR-002** `LOCK_ABSENT_GRACE` 는 `PRESENCE_TTL_SECONDS` 보다 크다. 같거나 작으면
  접속자 목록이 깜빡이는 순간에 잠금이 걷힌다.
- **FR-003** 잠금을 집거나 갱신하는 모든 경로는 **같은 자리에서** presence 도 올린다.
  두 수명이 갈리면 지금과 같은 불일치가 다시 생긴다.
- **FR-004** 보유자가 사라진 잠금은 **행 자체를 지운다**(숨기는 것이 아니다). 정리는
  스트림 한 바퀴마다, 그리고 **기동 시 한 번** 돈다 — 붙어 있는 창이 하나도 없을 때가
  유령이 가장 잘 남는 자리다.
- **FR-005** 창이 정상적으로 닫히면 TTL 을 기다리지 않고 즉시 푼다(현행 유지).
- **FR-006** 남의 살아 있는 잠금은 못 뺏는다. 보유자가 없어진 잠금만 집을 수 있다.
- **FR-007** 스트림이 끊긴 동안 화면은 **자기가 끊겼다는 것을 표시한다.** 잠금을 잡은
  채 끊겼으면 "잃을 수 있다"까지 말한다.
- **FR-008** 스트림이 돌아왔을 때 그 요소가 비어 있으면 **자동으로 다시 집는다**(현행 유지).
  남이 가져갔으면 읽기로 내리고 누구인지 보인다(현행 유지).
- **FR-009** AI 챗은 **요소를 고르는 순간** 남의 잠금을 확인하고, 막히면 LLM 을 부르기
  전에 배너·입력 잠금으로 알린다(현행 유지 — 이 스펙이 화면으로 재는 대상).
- **FR-010** 챗 화면의 선택 칩 id 와 잠금 id 는 **같은 값이어야 한다.** 다르면 배너도
  입력 잠금도 안 걸리고 서버 409 만 남는다. 검사가 양쪽에 같은 id 를 심지 않고
  **앱이 만든 값끼리** 맞대 본다.
- **FR-011** 무엇이 0건/빈 화면으로 끝나면 이유를 갈라서 남긴다 — `없음` · `막힘` ·
  `못 읽음` 은 다른 사건이다.

## 명시적 비목표

- **살아 있는 보유자에게서 뺏는 "강제 이어받기"는 안 만든다.** 창을 켜 둔 채 자리를
  비운 사람의 잠금은 이 스펙으로 안 풀린다 — 그건 사람 사이의 문제이고, 강제 인수는
  선점의 목적(겹쳐 쓰기 방지)을 정면으로 무너뜨린다. 화면은 **누가 잡고 있는지**를
  보여 주는 것까지만 한다.
- 문서 단위 잠금, 필드 단위 잠금, 편집 이력 병합(OT/CRDT)은 범위 밖이다.

## Success Criteria

- 창 둘 · 두 사람으로 **화면에서** 밟아 US1~US5 를 통과한다. API 로 질러서 재지 않는다.
- AI 챗은 **프롬프트 입력 → LLM 초안 → 승인 클릭**을 실제로 지난다. 안 지났으면
  "통과"라고 쓰지 않는다.
- 잠금이 걷히는 시간은 보유자가 **정말 사라졌을 때만** 걸리고, 그 값이 60초보다 짧다.
- 브라우저 강제 종료 · 백엔드 재시작 두 갈래에서 유령 잠금 0.
- 각 검사에 결함을 심어 무는 것을 확인한다. 파괴적 결함은 심지 않는다.
- 실 프로젝트를 고쳤으면 되돌린다. **되돌리기가 실패하면 검사도 실패한다.**
