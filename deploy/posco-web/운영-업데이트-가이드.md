# posco-web 운영 · 업데이트 가이드 — 고치고, 굽고, 사내 서버에 넣는다

처음 설치는 [서버-배포-가이드.md](서버-배포-가이드.md) §0-1 이다. 이 문서는 **설치가 끝난 뒤**,
코드를 고칠 때마다 같은 명령으로 되풀이하는 길이다. 2026-11-13 POSCO 현장(10.125.3.81)에서
실제로 밟은 것을 그대로 굳혔다.

```text
개발 PC ─push─► GitHub Actions ─굽기─► ghcr (web · architect-api :delivery)
   │                                        │
   └─ publish-images.ps1 ◄──pull·save───────┘
         │ tar + .sha256
         ▼
   GitHub Release (prerelease) ──curl(일반 계정 · 프록시)──► 사내 서버 update.sh
                                                              git pull · load · 바꿔 띄우기
```

사내 서버는 **github.com 에는 curl 로 닿고 ghcr.io 에는 못 닿는다**(프록시를 넘겨도 시간 초과).
그래서 이미지는 Release 로, 설정은 `git pull` 로 들어간다.

## 1. 지금 판의 짜임

### 1-1. 장 열한 개

| 장 | 이미지 | 어디서 오나 | healthcheck |
|---|---|---|---|
| web (nginx) | `robo-posco-web:delivery` | **CI** (frontend/** 등) | compose |
| architect-api | `robo-posco-architect-api:delivery` | **CI** (api/** 등) | compose |
| authority · authority-init | `robo-posco-authority:<납품판>` | 납품판 그대로 | 이미지 |
| graph-db · graph-bolt | `robo-posco-graph-db` · `-graph-bolt` | 납품판 그대로 | compose |
| analyzer · catalog · fabric · parser · gateway · wireframe | `robo-posco-*` | 납품판 그대로 | compose |

`<납품판>` = `0.1.0-wde10ff6c-afff41f36-scda199-rdel-swp`. 이 아홉 장은 10-30 납품 `robo-images.tar`
와 **같은 이미지**다(이름만 다르다). 고칠 일이 생기면 **architect-api · web 쪽에서 고친다** —
예: authority 가 JSON 으로 답하는 SWP 콜백을 architect-api 미들웨어가 HTML 로 바꿔 낸다(94db8eb).

### 1-2. 요청이 지나는 길

```text
브라우저 ─► web:8080 (nginx) ─ /api/** ─► architect-api:8000
                                            ├ /api/auth/** · /api/accounts/** · /api/projects/**
                                            │     └─► authority:59020 (넘긴다 · AuthorityProxyMiddleware)
                                            ├ /api/gateway/** ─► gateway ─► analyzer · catalog · fabric · parser
                                            └ 그래프 ─► graph-bolt(7687) ─► graph-db(5432)
밖으로 열린 포트는 web 하나(ROBO_WEB_PORT). 나머지는 compose 네트워크 안에서만.
```

- SWP 콜백(`/api/auth/sso/valid`)·로그인 로그(`auth.sso.validated`)는 **authority** 에 있다.
- 문서 업로드·생성(P-GPT 호출)은 **architect-api**, 레거시 코드 분석은 **analyzer**.

### 1-3. 폴더 (`deploy/posco-web/`)

| 파일 | 하는 일 | 서버에서 |
|---|---|---|
| `docker-compose.yml` | 통합 한 대짜리. **고치지 않는다**(값은 `.env`) | 쓴다 |
| `docker-compose.split.*.yml` | AP·DB 분할 — `make-split.py` 가 만든다 | 분할일 때만 |
| `.env` | 사람이 넣는 넷 + 비밀 넷(`init-env.sh`) | 서버에만 있다 · git 에 없다 |
| `authority-init.py` | 권한 서버 초기화 — 역할·표·권한. 다시 돌려도 안전 | `update.sh` 가 돌린다 |
| `tiktoken-cache/` | tiktoken 사전 둘 — 사내망은 받으러 못 나간다 | 바인드로 붙는다 |
| `analyzer-llm/*.yaml` | analyzer 의 gpt-4.1 설정·가격표 | 바인드로 붙는다 |
| `update.sh` | **서버에서** 새 판 받기·바꿔 띄우기 | 쓴다 |
| `publish-images.ps1` | **개발 PC 에서** 이미지 묶어 Release 에 | 안 쓴다 |
| `check.sh` · `init-env.sh` | 처음 설치 때 | 처음 한 번 |

## 2. 개발 쪽 — 고치고 굽고 올린다

```text
① posco-web 가지에서 고친다 → 시험 → push
     deploy/** 만 바꿨으면 굽지 않는다 → §3 의 --no-images 로 끝
     api/** · frontend/** · docker/Dockerfile.* 를 바꿨으면 Actions "posco-web images" 가 돈다
② Actions 가 초록인지 본다 (check → build 두 장)
     gh run list --repo uengine-oss/robo-architect --branch posco-web --limit 1
③ 묶어서 올린다 — 인터넷 되는 PC · Docker Desktop · gh 로그인
```

```powershell
cd <robo-architect>\deploy\posco-web
.\publish-images.ps1 -Tag posco-web-images-YYYY-MM-DD
```

- `revision` 줄이 **방금 push 한 커밋**인지 본다(CI 가 아직이면 옛것이 온다).
- 마지막 줄에 서버에서 칠 명령이 나온다: `bash update.sh <Tag> images.tar`
- 한 장만 바뀌었으면 `-Images robo-posco-architect-api:delivery -Asset api.tar` 처럼 줄인다.
- 올리기 전에 보고만 싶으면 `-DryRun`.

## 3. 사내 서버 — 받고 바꿔 띄운다

`robo-posco/deploy/posco-web` 에서, **sudo 없이**:

```bash
bash update.sh posco-web-images-YYYY-MM-DD
```

yml·가이드·authority-init 만 바뀐 판이면:

```bash
bash update.sh --no-images
```

`update.sh` 가 하는 일(손으로 할 때도 이 순서다):

```text
1 git pull --ff-only
2 curl 로 tar + .sha256 받기 → sha256sum -c           ⚠ curl 은 일반 계정(sudo 는 프록시를 버린다)
3 sudo docker load -i <tar>
4 compose 가 찾는 이미지가 다 있나 (O/X)
5 authority-init 다시 → architect-api 강제로 다시 → healthy 까지 기다림
  → 나머지 up → web 강제로 다시
6 sudo docker compose ps -a   → 11장 healthy · authority-init Exited (0)
```

되돌리기: `git checkout <옛 커밋> -- docker-compose.yml` → 이전 Release 의 tar 로 `bash update.sh <옛 Tag>`.
그래서 **이전 Release 는 다음 판이 확인될 때까지 지우지 않는다.**

### 내리고 올리기

```bash
sudo docker compose down                       # 컨테이너만 지운다 · 볼륨·이미지는 남는다
sudo docker compose up -d --wait --pull never  # 다시 올린다
```

⚠ `down -v` · `volume prune` · `system prune -a` · `image prune` 은 **쓰지 않는다** —
podman root 저장소를 msa-ez 와 같이 쓴다.

## 4. podman 에서 실제로 밟은 함정 (2026-11-13)

| 증상 | 원인 | 지금의 처리 |
|---|---|---|
| fabric 이 Running 인데 unhealthy · `SyntaxError ... import` | podman 이 healthcheck 인자를 **빈칸에서 쪼갠다** | 빈칸 없는 식으로(a6f4413) — 새 healthcheck 도 빈칸 없이 쓴다 |
| `dependency architect-api failed to start` · `.State.Health` nil | `docker save` 의 OCI tar 를 load 하면 **이미지의 HEALTHCHECK 가 빠진다** | web · architect-api 의 healthcheck 를 compose 에 적었다(8f8d625) |
| load 했는데 옛 코드가 돈다 | **같은 태그**를 덮으면 compose 가 바뀐 줄 모른다 | `update.sh` 가 강제로 다시 만든다 |
| `/api/auth/provider` 502 · "인증 설정 확인 중" | architect-api 만 다시 만들면 nginx 가 **옛 IP** 를 붙든다 | web 을 마지막에 다시(`update.sh`) |
| `docker compose exec` 가 안 된다 | podman 의 docker 흉내 한계 | `sudo podman exec robo-posco-web-<장>-1 …` |
| `sudo docker compose pull` 시간 초과 | sudo 가 프록시를 버린다 · 넘겨도 ghcr 불통 | Release + curl |
| 스크립트가 `$'\r'` · `invalid option` | 화면에서 복사해 만든 파일에 CRLF | 파일은 `git pull` 로만 받는다 · 급하면 `sed -i 's/\r$//'` |
| `HTTPSConnectionPool(openaipublic.blob.core.windows.net)` | tiktoken 이 사전을 받으러 나간다 | `tiktoken-cache/` 를 붙였다(86a0aff) |
| Figma 연결 코드 503 "중앙 권한 저장소…" | 제한 역할에 프로젝트 목록 읽기 권한이 없다 | authority-init 2-c(86a0aff) |

현장 터미널은 붙여 넣으면 따옴표가 둥근 따옴표로 바뀌고 긴 줄이 잘린다 — 그래서 명령을
스크립트로 묶었다. 긴 주소는 변수로 나눠 치고 `echo` 로 확인한다.

## 5. 들여다보기

```bash
sudo docker compose ps -a
sudo docker compose logs --since 20m architect-api | tail -50          # 문서 업로드 · 생성 · P-GPT
sudo docker compose logs --since 20m authority | grep -e auth.sso -e auth.signin
sudo podman inspect robo-posco-web-<장>-1 | grep -i -A3 output | tail -8   # healthcheck 가 뭐라 했나
sudo podman inspect robo-posco-web-architect-api-1 --format {{.Image}}   # 어느 이미지로 도나
```

어느 커밋이 올라와 있나: `sudo docker image inspect ghcr.io/uengine-oss/robo-posco-architect-api:delivery`
의 라벨 `org.opencontainers.image.revision`.
