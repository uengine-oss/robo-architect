### ③ 이미지를 서버에 올린다 — **가·나 중 하나만**

**③-가. ghcr.io 에 닿는다 — 할 일 없다.** ⑦ 의 `up` 이 열한 장을 받는다(이미지는 public 이라
`docker login` 도 필요 없다). 받는 데 몇 분 걸리니 미리 받아 두려면:

```bash
docker compose pull
```

**③-나. 닿지 않는다 — 인터넷 되는 PC 에서 tar 를 만들어 옮긴다.**
PC 에서(Windows PowerShell · 클론 폴더 안):

```powershell
$tags = Select-String -Path deploy\posco-web\docker-compose.yml -Pattern '^\s+image:\s*(\S+)' | ForEach-Object { $_.Matches[0].Groups[1].Value } | Sort-Object -Unique; $tags | ForEach-Object { docker pull $_ }; docker save -o $HOME\Desktop\images.tar $tags; "{0:N1} GB" -f ((Get-Item $HOME\Desktop\images.tar).Length/1GB)
```

`images.tar` **한 장만** 서버로 옮겨(USB · scp · Portainer→Images→Import) 넣는다:

```bash
docker load -i images.tar
```

> **tar 가 1~2GB 로 작아도 정상이다** — 열한 장의 docker 표시 합은 7.6GB 지만 공유 레이어를
> 한 번만, 압축해서 담는다(2026-11-12 실측 1.4GB · 안에 열한 장 다 들어 있었다).
> ⚠ 형식이 **OCI** 다(Docker 29.7.2 + containerd 저장소). `podman load` 와 **Docker 25 이상**은
> 그대로 읽는다. 서버가 더 낮아 거부하면 PC 의 Docker Desktop 에서 **"Use containerd for
> pulling and storing images" 를 끄고** 위 줄을 다시 돌린다 — 옛 형식으로 나온다.
> `docker version --format '{{.Server.Version}}'` 으로 먼저 본다.
> PC 에서 bash 를 쓸 거면 한 줄이다 — `bash deploy/posco-web/bundle.sh ~/b --images`.
> ⚠ PowerShell 에서 `bash` 라고 치면 **WSL** 이 떠서 WSL 안 `/home/…` 으로 들어간다.

**③ 공통 — 열한 장이 서버에 있는지 댄다.** ③-가 면 `X` 가 나오는 게 정상이다(⑦ 이 받는다).
③-나 면 **`X` 가 하나도 없어야** 한다.

```bash
grep -h 'image:' docker-compose.yml | sed 's/.*image: *//' | sort -u | while read -r t; do docker image inspect "$t" >/dev/null 2>&1 && echo "O $t" || echo "X $t"; done
```

### ⑤ 넷을 채운다

```bash
vi .env
```

```text
ROBO_PUBLIC_URL    설계자가 열 주소. scheme://host:port, 경로 없이   예) http://10.10.0.5:8080
ROBO_ADMIN_EMPNO   최초 관리자 SWP 사번                             예) 1234567
ROBO_AI_BASE_URL   P-GPT 주소 (…/v1)
ROBO_AI_API_KEY    P-GPT 키 하나
                   ↑ 넷 다 파일 맨 위(18·21·24·25줄). 나머지는 손대지 않는다
                   ROBO_DB_SERVER_IP 는 통합 1대면 CHANGE_ME 그대로 둔다
                   8080 이 이미 쓰이면 ROBO_WEB_PORT 도 바꾼다(그러면 ROBO_PUBLIC_URL 도 같이)
```

**vi 로 고치는 법 — 커서를 움직일 필요 없다.** `vi .env` 로 들어가 아래 **다섯 줄을 그대로 치고**
각 줄마다 Enter 를 누른다(`:` 부터 친다 · 값만 자기 것으로 바꾼다). `|` 가 구분자라서 주소의
`/` 를 escape 하지 않아도 된다:

```text
:%s|^ROBO_PUBLIC_URL=.*|ROBO_PUBLIC_URL=http://10.10.0.5:8080|
:%s|^ROBO_ADMIN_EMPNO=.*|ROBO_ADMIN_EMPNO=1234567|
:%s|^ROBO_AI_BASE_URL=.*|ROBO_AI_BASE_URL=http://pgpt.사내/v1|
:%s|^ROBO_AI_API_KEY=.*|ROBO_AI_API_KEY=받은키|
:wq
```

```text
vi 생존 키   i 입력 시작 · Esc 입력 끝 · :wq 저장하고 나가기 · :q! 버리고 나가기
            /이름 찾기(n 다음) · dd 한 줄 지우기 · u 되돌리기
⚠ 값에 | 가 들어 있으면 구분자를 바꾼다 — :%s#^이름=.*#이름=값#
⚠ 끝에 공백·따옴표를 붙이지 않는다. 주소는 scheme://host:port 로 끝낸다(경로·슬래시 없이)
```

**vi 가 손에 안 익으면 셸에서 한 줄로 끝낼 수도 있다**(2026-11-12 실측 · 네 줄 다 바뀐다):

```bash
sed -i "s|^ROBO_PUBLIC_URL=.*|ROBO_PUBLIC_URL=http://10.10.0.5:8080|; s|^ROBO_ADMIN_EMPNO=.*|ROBO_ADMIN_EMPNO=1234567|; s|^ROBO_AI_BASE_URL=.*|ROBO_AI_BASE_URL=http://pgpt.사내/v1|; s|^ROBO_AI_API_KEY=.*|ROBO_AI_API_KEY=받은키|" .env
```

> ⚠ 이 줄은 **키가 셸 히스토리에 남는다.** 그게 싫으면 vi 로 하거나, 뒤에
> `history -d $((HISTCMD-1))` 로 그 줄만 지운다.

**채워졌는지 눈으로 확인한다** — 값은 안 찍고 **길이만** 본다:

```bash
grep -nE '^(ROBO_PUBLIC_URL|ROBO_ADMIN_EMPNO|ROBO_AI_BASE_URL)=' .env; awk -F= '/^ROBO_AI_API_KEY=/{printf "%s = %d자\n", $1, length($2)}' .env; grep -c CHANGE_ME .env
```

```text
마지막 숫자  통합 1대면 **1** 이어야 한다(분할용 ROBO_DB_SERVER_IP 하나만 남는다)
            0 이면 분할 IP 까지 채운 것 · 2 이상이면 **아직 덜 채웠다** → ⑥ 이 이름을 대며 멈춘다
```

### msa-ez 를 해 본 사람에게 — **순서는 같고, 값 넣는 자리만 다르다**

같은 조직이 이미 msa-ez v1.0.30 을 이 방식으로 돌린다. 단계는 **그대로 겹친다**.

| msa-ez v1.0.30 | 이 판 | 다른가 |
|---|---|---|
| ① `git checkout release/v1.0.30` | ② 받기 (`git clone -b posco-web` + `bundle.sh`) | 묶음 폴더를 따로 만든다 — 저장소를 서버에서 수정하지 않는다 |
| ② 토폴로지별 compose 고르기 (단일/split.db/split.ap) | ① 고르기 (**같은 세 파일 이름**) | 같다 |
| ③ **compose yml 안의 `<DB_PASSWORD>` 등 자리표를 직접 채운다** | ③ **`.env` 하나를 채운다**(`init-env.sh` 가 비밀을 난수로) | ⚠ **여기만 다르다** — 아래 |
| — | ④ `check.sh` (띄우기 전 검사) | 이 판에만 있다 |
| ④ `docker compose pull` → `up -d` → `ps` | ⑤ `up -d --wait` → `ps` | `--wait` 는 전부 healthy 까지 기다린다(아래 podman 주의) |
| ⑤ DB 서버 먼저, AP 서버 나중 | 같다 | 같다 |
| ⑥ psql 로 표 수 · `curl :5757/health` · 브라우저 로그인 | ⑥ `/healthz` · `/api/health` · 브라우저 SWP 로그인 | 같은 종류 |

```text
⚠ 값을 **yml 이 아니라 .env** 에 두는 이유 — msa-ez 가 그 값을 치르고 있다
  msa-ez 는 같은 `<DB_PASSWORD>` 를 **네 곳**에 손으로 적어야 하고, 두 생성기의 키
  자리표 철자가 서로 다르다(`your-openai-api-key-here` ↔ `your-open-api-key-here`).
  그리고 yml 을 고쳐 두었으므로 올릴 때마다 README 가 **백업 → `git checkout --` 로
  되돌리기 → 자리표 다시 채우기**를 시킨다.
  이 판은 `${ROBO_AI_API_KEY:?}` 처럼 **가리키기만** 해서 값이 한 곳에만 있고,
  `.env` 는 git 이 무시하므로 올릴 때 충돌하지 않는다. 분할이면 `.env` 한 파일을
  두 서버에 똑같이 놓는다(msa-ez 는 두 yml 을 각각 고친다).
⚠ 그래서 **`check.sh` 를 꼭 돌린다** — `${…:?}` 치환을 그 compose 구현이 받는지
  `[4] compose config` 가 띄우기 전에 확인한다. podman 이면
  `COMPOSE="podman compose" bash check.sh` 로 **그 구현으로** 본다.
```

## 1. 어떻게 올리나 — **하나만 고른다**

| | 통합 서버 1대 | AP·DB 2대 |
|---|---|---|
| yml | `docker-compose.yml` | DB 서버 `docker-compose.split.db.yml` · AP 서버 `docker-compose.split.ap.yml` |
| DB 서버에 뜨는 것 | — | graph-db · graph-bolt · authority (+ authority-init 은 한 번 돌고 끝) |
| AP 서버에 뜨는 것 | 전부(11개 + init 한 번) | web(nginx) · architect-api · analyzer · catalog · fabric · parser · gateway · wireframe |
| 밖으로 여는 포트 | 8080 하나 | AP: 8080 · DB: 5432 · 7687 · 59020 (**방화벽으로 AP 서버만** — §7) |
| 언제 | 처음 올릴 때 · 사용자가 적을 때 | DB 를 따로 백업·관리해야 할 때 (msa-ez 분할과 같다) |

```text
브라우저 ─► web(nginx :8080) ─/api─► architect-api ─► authority (SWP 로그인·승인·공유)
                │ 빌드된 화면만                  ├─► gateway ─► analyzer·catalog·fabric·parser
                                                ├─► wireframe (와이어프레임 그리기)
                                                └─► graph-bolt / graph-db (데이터 전부)
```

## 2. 준비물

| 무엇 | 확인 |
|---|---|
| 리눅스 서버 (amd64) | `uname -m` → `x86_64` |
| docker + compose v2 **또는** podman + compose | `docker compose version` / `podman compose version` |
| git 또는 묶음 파일 | §3 |
| 이미지 받을 길 | GHCR 에 닿거나(`curl -sI https://ghcr.io` 가 응답) **또는** 이미지 묶음 tar |
| P-GPT 주소·키 | 사내 AI 담당에게 받는다 |
| 최초 관리자 사번 | SWP 사번(sp_empno) |
| 서버 주소 | 설계자가 브라우저로 열 주소 (예: `http://10.x.x.x:8080`) |

> **서버에 따로 깔 것은 없다**(2026-11-12 확인). `python3` 가 없으면 `check.sh` 는 분할 파일
> 대조 한 가지만 "건너뛴다" 고 적고 지나가며(그 검사는 굽는 쪽 CI 가 이미 한다), `openssl` 이
> 없으면 `init-env.sh` 가 `/dev/urandom` 으로 비밀을 만든다. 필요한 것은 docker/podman · git ·
> 그리고 묶음을 들고 올 때만 `sha256sum` 이다.

> ⚠ **같은 서버에 msa-ez 가 있으면 포트가 겹친다.** msa-ez 도 프런트에 **8080**, DB 서버에
> **5432** 를 쓴다. 그때는 §4 의 `ROBO_WEB_PORT` · `ROBO_DB_PG_PORT` 를 다른 숫자로 바꾼다.

> ⚠ **아래 상자 둘은 Windows PC 전용이다 — 리눅스 서버에서는 건너뛴다.** 서버에서 칠 명령은
> §3 부터이고, 그 아래 ```bash``` 상자는 **전부 그대로 붙여 넣으면 된다**(Windows 경로·
> PowerShell 구문이 섞인 줄은 이 상자 둘 말고는 없다 · 2026-11-12 전수 확인).
>
> **이 가이드의 명령은 전부 리눅스 bash 다.** Windows PC 에서 미리 해 볼 때는 **Git Bash 안에서**
> 친다. PowerShell 창이면 먼저 이 한 줄로 들어간다:
>
> ```powershell
> & "C:\Program Files\Git\bin\bash.exe" -l
> ```
>
> PowerShell 에서 그냥 치면 막힌다 — `sha256sum` 이 없고, Windows PowerShell 5.1 은 `&&` 를
> 모르고, `bash` 라고 치면 Git Bash 가 아니라 **WSL** 이 떠서 `/c/…` 경로가 안 통한다.
> 경로는 `/c/Users/…` 꼴로 쓰고, 로컬 시험이면 `ROBO_PUBLIC_URL=http://127.0.0.1:8080` 으로 둔다.
>
> **PowerShell 창에서 그대로 하려면** Git Bash 를 **경로로** 부른다. 한 줄씩 친다
> (Windows PowerShell 5.1 에서 이 순서 그대로 돌려 확인했다 · 2026-11-10):
>
> ```powershell
> cd C:\robo\robo-architect      # ← 체크아웃 자리. **자기 PC 경로로 바꾼다**
> git pull
> & "C:\Program Files\Git\bin\bash.exe" deploy/posco-web/bundle.sh /c/robo-posco-web
> cd C:\robo-posco-web
> & "C:\Program Files\Git\bin\bash.exe" init-env.sh
> notepad .env
> & "C:\Program Files\Git\bin\bash.exe" check.sh
> docker compose up -d --wait
> ```

## 3. 받기

### 인터넷(GHCR)에 닿는 서버 — 보통 이쪽

```bash
git clone -b posco-web https://github.com/uengine-oss/robo-architect.git
bash robo-architect/deploy/posco-web/bundle.sh ~/robo-posco-web
cd ~/robo-posco-web
```

이미지 열한 장은 **public** 이라 `docker login` 이 필요 없다. 띄울 때 compose 가 받는다.
저장소도 **public** 이라 클론에 토큰이 필요 없다. `.git` 이 200MB 쯤이니 `--depth 1` 을 붙여도 된다.

#### 묶지 않고 **클론 폴더에서 바로** 쳐도 된다

`bundle.sh` 는 **순수 복사**다(파일 12개를 새 폴더에 `cp` 하는 것뿐 · 고쳐 쓰는 것 없음).
그래서 `deploy/posco-web/` 안에서 그대로 쳐도 **같다** — 바인드 마운트가 물는 호스트 파일
둘(`authority-init.py` · `analyzer-llm/openai_gpt41.yaml`)이 저장소에 **같은 자리로** 들어 있다.

```bash
git clone -b posco-web --depth 1 https://github.com/uengine-oss/robo-architect.git
cd robo-architect/deploy/posco-web     # ← 묶음 폴더 대신 여기서 전부 한다
bash init-env.sh && vi .env && bash check.sh && docker compose up -d --wait
```

> `.env` 는 `.gitignore` 에 있다 — 비밀을 채워도 저장소가 더러워지지 않고 `git pull` 이 막히지
> 않는다. `.sh` 는 `.gitattributes` 가 **LF 로 못박아** 둬서 Windows 를 거쳐도 shebang 이 안 깨진다.
> ⚠ **`main` 에는 이 폴더가 없다** — 가지는 `posco-web` 이다. `-b posco-web` 을 빼면 `cd` 가 실패한다.

> ⚠ **vi 로 고치는 곳은 `.env` 다. yml 은 아니다**(§5 와 같은 말). yml 에 박혀 있는 값은
> **이미지 태그 열한 줄뿐**이고, 공개 포트조차 `${ROBO_WEB_BIND:-0.0.0.0}:${ROBO_WEB_PORT:-8080}`
> 처럼 `.env` 에서 온다. 그래도 yml 을 손봐야 하면 **`docker-compose.override.yml`** 에 적는다 —
> compose 가 자동으로 겹쳐 읽고, 추적되지 않으니 다음 `git pull` 과 **부딪치지 않는다**.
> (yml 을 직접 고치면 pull 이 충돌로 멈춘다.)

> ⚠ **폐쇄망이면 클론 커밋과 `images.tar` 가 맞아야 한다.** yml 의 태그는 커밋마다 움직인다
> (`web` · `architect-api` 는 `posco-web-<커밋7자>`). tar 를 만든 뒤에 클론하면 태그가 옮겨 가
> 있을 수 있고, 그 이미지는 tar 에 **없다** — 그러면 `up` 이 받으러 나가서 **멈춘다**.
> 올리기 전에 한 줄로 댄다:
>
> ```bash
> grep -h 'image:' docker-compose.yml | sed 's/.*image: *//' | sort -u | while read -r t; do
>   docker image inspect "$t" >/dev/null 2>&1 && echo "O $t" || echo "X $t   ← 서버에 없다"
> done
> ```
>
> `X` 가 나오면 **tar 를 만든 커밋으로** `git checkout <커밋>` 하거나, 그 이미지를 더 넣는다.

### 인터넷이 없는 서버 — 다른 PC 에서 묶어 온다

> 서버가 GHCR 에 닿으면 **이 절은 건너뛴다.** `SHA256SUMS` · `images.tar` 는 아래
> `bundle.sh … --images` 가 **그 출력 폴더에만** 만든다 — 저장소의 `deploy/posco-web` 에는 없다.

인터넷 되는 PC(도커 있음)에서:

```bash
git clone -b posco-web https://github.com/uengine-oss/robo-architect.git
cd robo-architect/deploy/posco-web
docker compose --env-file .env.example -f docker-compose.yml pull
bash bundle.sh /tmp/robo-posco-web --images
```

`/tmp/robo-posco-web` 폴더를 통째로 서버에 옮긴 뒤 서버에서:

```bash
cd ~/robo-posco-web
sha256sum -c SHA256SUMS
docker load -i images.tar
```

> `pull` 에 `--env-file .env.example` 을 주는 이유: yml 이 필수 값(`${…:?}`)을 요구해서, `.env` 가
> 없으면 받기 전에 멈춘다. 받기만 할 때는 견본 값으로 충분하다.
>
> `image-ids.txt` 에 태그 → image ID 가 적혀 있다. `docker image inspect <태그> --format '{{.Id}}'`
> 와 같아야 한다. 납품판 아홉 장은 **납품 매니페스트와 같은 ID** 다.

#### Portainer 로 이미지를 올릴 때 — **compose 는 묶음 폴더에서 친다**

사내망에서 Portainer 로 tar 를 올려 쓰던 방식 그대로 된다. `images.tar` 는 `docker save`
로 만든 것이고 Portainer 의 **Images → Import** 가 곧 `docker load` 다. 태그가 그대로
되살아나므로 compose 는 **받으러 나가지 않는다**(`up` 의 기본 pull 정책은 "없을 때만").

```text
① Portainer → Images → Import → images.tar          (= docker load -i images.tar)
② 열한 장이 다 들어왔는지 image-ids.txt 와 대조
③ compose 는 **서버 셸에서, 묶음 폴더 안에서** 친다 — `cd ~/robo-posco-web && docker compose up -d --wait`
```

> ⚠ **③ 을 "Portainer 스택 편집기에 yml 붙여넣기" 로 바꾸면 안 뜬다.** 이 compose 는 묶음
> 폴더의 **호스트 파일 둘**을 물고 있다. 붙여넣기 스택은 그 폴더가 아니라 Portainer 가 만든
> 임시 폴더에서 돌아서 둘 다 없다.
>
> ```text
> ./authority-init.py                    authority-init 이 실행하는 파일 그 자체.
>                                        **이미지 안에 없다**(2026-11-12 실측: 이미지에서
>                                        `python /app/authority_init.py` → "can't open file").
>                                        이게 없으면 authority-init 이 죽고, architect-api 는
>                                        `service_completed_successfully` 를 기다리므로
>                                        **영영 안 뜬다**
> ./analyzer-llm/openai_gpt41.yaml       OpenAI 설정을 쓸 때 analyzer 가 읽는다. 마운트는 무조건이다
> ./analyzer-llm/llm_pricing.yaml        analyzer 가격표. 없으면 **레거시 분석이 거부된다**
> .env                                   값 전부. Portainer 스택이면 환경변수 화면에 따로 넣어야 한다
> ```
>
> 정 Portainer 스택으로 관리하고 싶으면 두 파일을 스택 폴더에 같이 두거나, 스택 이름을
> **`robo-posco-web`** 로 맞춘다 — 스택 이름이 yml 의 `name: robo-posco-web` 을 **덮기 때문에**
> 이름이 다르면 볼륨도 `<스택이름>_graph_data` 로 새로 생긴다. 다음 판에서 이름을 바꾸면
> **데이터가 사라진 것처럼 보인다.**

## 4. `.env` 채우기 — **사람이 손대는 곳은 여기뿐이다**

```bash
bash init-env.sh
```

`init-env.sh` 가 하는 일 셋: ① `.env` 가 없으면 `.env.example` 을 복사하고 ② **비밀 넷(§4-②)을
난수로 채우고** ③ **당신이 채울 이름만 찍는다.** 다시 돌려도 안전하다 — 이미 채운 값은 안
건드린다.

**찍히는 그대로가 할 일 목록이다.** 통합 서버에서 돌린 실제 출력:

```text
.env 를 만들었다 (.env.example 복사)
  채움  ROBO_GRAPH_PASSWORD (48자)
  채움  ROBO_AUTHORITY_DB_PASSWORD (48자)
  채움  AUTH_JWT_SECRET (48자)
  채움  AUTH_ROLE_SECRET (48자)

사람이 채울 것 — .env 를 열어 적는다:
  ROBO_PUBLIC_URL
  ROBO_ADMIN_EMPNO
  ROBO_AI_BASE_URL
  ROBO_AI_API_KEY
  ROBO_DB_SERVER_IP   (AP·DB 분할 배포일 때만 — 통합 서버면 그대로 둔다)
다 채우면:  bash check.sh
```

```text
⇒ 통합 서버는 **넷**, 분할이면 `ROBO_DB_SERVER_IP` 까지 **다섯**이다.
  뜻은 아래 §4-①(넷) · §4-④(DB 서버 주소) 에 있다.
  **`.env` 안에서도 같은 순서로 나온다** — 앞의 넷은 파일 **맨 위**에 모여 있고
  (18·21·24·25번째 줄), `ROBO_DB_SERVER_IP` 만 포트 절(68번째 줄)에 떨어져 있다.
  값 줄은 모두 26개 — **채울 것 넷(분할 다섯) · 스크립트가 채운 것 넷 · 그대로 둘 것 나머지**다.
  나머지는 **그대로 두면 된다** — 선택 셋(§4-① 아래쪽) · 고정값(§4-③) ·
  포트(§4-④) · 메모리 상한(§4-⑤).
  빠뜨리면 `check.sh` 가 **이름을 대며 멈춘다** — 외우지 않아도 된다.
```

### 4-① 사람이 정하는 값 — 통합 **넷** · 분할 **다섯**

| 이름 | 무엇을 적나 | 예 |
|---|---|---|
| `ROBO_PUBLIC_URL` | 설계자가 브라우저로 여는 주소. **scheme://host:port, 경로 없이** | `http://10.10.0.5:8080` |
| `ROBO_ADMIN_EMPNO` | 최초 관리자 사번. 이 사람이 다른 사람을 승인한다 | `1234567` |
| `ROBO_AI_BASE_URL` | P-GPT 주소 (설치본 `OPENAI_BASE_URL` 과 같은 값) | `http://…/v1` |
| `ROBO_AI_API_KEY` | P-GPT 키 **하나**. 이 한 값이 **네 서비스 · 여덟 칸**으로 퍼진다(architect-api · analyzer · catalog · fabric) | |
| `ROBO_DB_SERVER_IP` | **분할 배포에서만.** DB 서버의 사내망 IP — 통합 서버면 그대로 둔다(§4-④) | `10.10.0.6` |

위 넷(분할이면 다섯)이 **반드시** 채울 값이다. 아래 셋은 **선택** — 그대로 둬도 된다.

| 선택 | 무엇을 적나 | 기본 |
|---|---|---|
| `ROBO_ANALYZER_LLM_CONFIG` | 레거시 분석 모델 설정 — **AI 주소와 짝**. P-GPT 면 `pgpt`, OpenAI 면 `openai_gpt41` | `pgpt` |
| `SWP_SSO_LOGIN_URL` · `SWP_SSO_VALID_CHECK_URL` · `SWP_SSO_REDIRECT_URL` | **비워 둔다** — 비우면 가동계 기본값. 개발계로 붙을 때만 채운다 | (빈 값) |
| `ROBO_APPROVAL_REQUIRED` | `true` = 새 사용자는 관리자 승인 후 사용 · `false` = 바로 사용 | `true` |

> **P-GPT 대신 OpenAI 를 쓰려면** (사내망 밖 시험 등) 세 줄을 함께 바꾼다:
>
> ```text
> ROBO_AI_BASE_URL=https://api.openai.com/v1
> ROBO_AI_API_KEY=<OpenAI 키>
> ROBO_ANALYZER_LLM_CONFIG=openai_gpt41
> ```
>
> 세 번째 줄을 빼먹으면 **레거시 분석만** P-GPT 로 간다 — analyzer 는 주소를 환경변수가 아니라
> 설정 파일에서 읽기 때문이다. `check.sh` 가 이 짝이 어긋나면 멈춘다. 두 설정 모두 gpt-4.1 이다.

> ⚠ **`ROBO_PUBLIC_URL` 이 틀리면 SWP 로그인이 거부된다.** SWP 가 로그인 후 이 주소로만
> 돌려보낸다. 설계자가 **IP 로 여는지 이름으로 여는지**, 포트까지 똑같이 적는다.

### 4-② 자동으로 만드는 값 — **넷** (처음 한 번만)

위의 `init-env.sh` 가 채운다 — 손으로 만들 필요 없다. `CHANGE_ME` 인 것만 채우므로 두 번
돌려도 바뀌지 않는다.

| 이름 | 무엇 | ⚠ |
|---|---|---|
| `ROBO_GRAPH_PASSWORD` | 그래프 저장소(DB) 소유자 비밀번호 | **볼륨을 처음 만들 때 굳는다.** 나중에 바꾸면 전부 인증 실패 |
| `ROBO_AUTHORITY_DB_PASSWORD` | 권한 서버의 제한 DB 역할 | |
| `AUTH_JWT_SECRET` | 로그인 토큰 서명 | 바꾸면 전원 재로그인 |
| `AUTH_ROLE_SECRET` | 사용자별 DB 계정 비밀번호의 씨앗 | **바꾸면 기존 프로젝트를 못 연다** |

> 비밀 값은 **영문·숫자만** 쓴다(DB 주소 문자열 안에 들어가므로 `@ : / #` 는 안 된다).
> 위 명령은 16진수만 만들므로 안전하다.

### 4-③ 고정값 — 바꾸지 않는다

```text
ROBO_GRAPH_USER=robo
ROBO_GRAPH_DESIGN=robo
ROBO_GRAPH_ANALYSIS=analyzer_run     설계 graph 와 **달라야 한다** (같으면 분석이 설계를 지운다)
```

### 4-④ 포트·주소

| 이름 | 통합 | 분할 | 기본 |
|---|---|---|---|
| `ROBO_WEB_BIND` | ✔ | AP | `0.0.0.0` (모든 주소에서 브라우저 접속) |
| `ROBO_WEB_PORT` | ✔ | AP | `8080` — msa-ez 와 겹치면 바꾼다 |
| `ROBO_DB_SERVER_IP` | — | **둘 다** | DB 서버의 사내망 IP. **`0.0.0.0` 금지** |
| `ROBO_DB_PG_PORT` · `ROBO_DB_BOLT_PORT` · `ROBO_AUTHORITY_PORT` | — | 둘 다 | `5432` · `7687` · `59020` |

### 4-⑤ 메모리 상한 — **기본은 걸지 않는다**

| 이름 | 무엇 | 기본 |
|---|---|---|
| `ROBO_MEM_API` · `ROBO_MEM_ANALYZER` · `ROBO_MEM_PARSER` · `ROBO_MEM_GATEWAY` | 그 서비스가 쓸 수 있는 메모리 상한 | `0` = **제한 없음** |

통합 서버는 한 대에 열한 서비스가 같이 산다. 상한이 없으면 분석 하나가 번질 때 같은 서버의
그래프 저장소까지 굶는다. 그래서 손잡이를 뒀다 — 다만 **기본은 0 이다.** 조여서 OOM 으로
죽는 쪽이 더 나쁘고, 돌 때의 값을 아직 아무도 안 쟀다.

```bash
docker compose stats --no-stream     # 분석을 한 건 돌리는 **중에** 본다
```

```text
쉬는 중에 잰 값 (2026-11-11 · 같은 이미지)
  parser 676MiB · gateway 518MiB · analyzer 228MiB · catalog 126MiB
  fabric 77MiB · graph-db 74MiB · wireframe 49MiB · graph-bolt 4MiB
⚠ parser·gateway 는 JVM 이다 — 상한을 걸면 **기본 힙도 그 비율로(25%) 줄어든다.**
  큰 저장소 파싱이 실패하는 쪽이 더 나쁘니 넉넉히 준다(예: 4g)
⚠ 건 값이 **실제로 들어갔는지** 본다 — 조용히 무시하는 compose 구현이 있다:
    docker inspect <컨테이너> --format '{{.HostConfig.Memory}}'     ← 0 이면 안 걸렸다
```

> **분할이면 `.env` 를 한 번 만들어 두 서버에 똑같이 놓는다.** 한쪽만 다르면 AP 가 DB 에
> 인증 실패하거나, SWP 콜백이 거부된다(콜백 허용 주소는 **DB 서버의** 권한 서버가 본다).

### 4-⑥ 설치본 가이드 이름 → 이 판의 이름

| 설치본 가이드에서 | 이 판 `.env` |
|---|---|
| `$AI_KEY` (다섯 이름에 같은 값) | `ROBO_AI_API_KEY` |
| msa-ez 의 `OPENAI_BASE_URL` | `ROBO_AI_BASE_URL` |
| `$GRAPH_HOST` · `SERVER_IP` · `ROBO_GRAPH_BIND` · `ROBO_AUTHORITY_BIND` | `ROBO_DB_SERVER_IP` (분할만) |
| `$GRAPH_PASSWORD` · `GRAPH_PW` | `ROBO_GRAPH_PASSWORD` |
| `$ROLE_SECRET` · `$JWT_SECRET` | `AUTH_ROLE_SECRET` · `AUTH_JWT_SECRET` |
| `AUTH_RT_PW` | `ROBO_AUTHORITY_DB_PASSWORD` |
| `ADMIN_EMPNO` · `APPROVAL_REQUIRED` | `ROBO_ADMIN_EMPNO` · `ROBO_APPROVAL_REQUIRED` |
| `AUTH_CALLBACK_ALLOWLIST` | `ROBO_PUBLIC_URL` |
| `$DEV_*` (시험 로그인) | **없다** — 서버 판은 개발 로그인을 막는다 |
| `ROBO_INGESTION_URL` · `OPER_PW` | **없다** |

## 5. yml 에는 무엇이 들어 있나 — **고칠 곳은 없다**

yml 은 `.env` 의 값을 **읽기만** 한다. 사람이 yml 을 고치지 않는 이유:

- yml 은 **저장소에 들어 있고 공개다.** 비밀을 적으면 그대로 새어 나간다
  (msa-ez 는 yml 에 값을 직접 적지만 이 판은 그러지 않는다).
- 분할 두 파일은 통합 파일에서 **자동으로 만든다.** 한 파일만 고치면 셋이 어긋난다
  (`check.sh` 가 어긋남을 잡고 멈춘다).

yml 이 정해 둔 것 — 참고로만 본다:

| 묶음 | 내용 | 어디서 값을 받나 |
|---|---|---|
| 이미지 태그 | 열한 장 전부 고정(`latest` 없음). 납품판 아홉 장 `0.1.0-…-rdel-swp`, CI 두 장 `posco-web-<커밋>` | CI 가 박는다 |
| 접속 주소 | 서비스끼리 `http://gateway:9000` 같은 내부 이름. 분할 AP 는 DB 서버 IP | `ROBO_DB_*` |
| 로그인 | `AUTH_PROVIDER=swp` · `AUTH_ENFORCE=true` · 개발 로그인 끔 | 고정 |
| 제품 설정 | 모델 이름(`gpt-4.1`) · 검색·분석 파라미터 — **설치본 값 그대로** | 고정 |
| 비밀·사이트 값 | `${ROBO_AI_API_KEY:?}` 처럼 **`.env` 를 가리키기만** 한다 | `.env` |
| 볼륨 | `graph_data`(데이터 전부) · `shared_data`(업로드 소스) · `workspace`(코드 생성 대상) | — |

**정말 yml 을 바꿔야 하는 경우 둘** — 둘 다 개발 쪽 일이다:

```text
이미지 새 판으로 올림   개발 쪽 CI 가 태그를 박아 커밋한다 → 서버는 git pull + 묶음 다시 만들기
제품 설정을 바꿈        docker-compose.yml(통합)만 고치고  python make-split.py
```

## 7. 띄우기

### 통합 서버

```bash
docker compose up -d --wait
```

### 분할 — **DB 서버 먼저**

```bash
# DB 서버
docker compose -f docker-compose.split.db.yml up -d --wait
```

```bash
# AP 서버 (DB 서버가 다 뜬 뒤)
docker compose -f docker-compose.split.ap.yml up -d --wait
```

처음에는 이미지 받기 때문에 오래 걸린다. `--wait` 는 전부 healthy 가 될 때까지 기다린다.

> ⚠ **`--wait` 를 못 받는 compose 구현이 있다**(podman compose 의 일부 판). 그러면
> `unknown flag: --wait` 로 **띄우지도 못한다.** msa-ez 는 그래서 `up -d` 뒤에 `ps` 로
> 본다. 같은 식으로 하면 된다 — 결과는 같고 기다려 주지만 않는다:
>
> ```bash
> docker compose up -d
> docker compose ps --format '{{.Service}}  {{.Status}}'   # 전부 healthy 가 될 때까지 몇 번 본다
> ```

> ⚠ **분할 판은 DB 포트를 방화벽으로 좁힌다 — compose 가 해 주지 않는다.** yml 은 5432 ·
> 7687 · 59020 을 DB 서버의 사내망 IP 에 **묶기만** 하고, 그러면 같은 망의 아무 PC 에서나
> 닿는다. **Bolt(7687)는 평문 인증**이라 그대로 두면 안 된다. DB 서버에서 AP 서버만 들이는
> 규칙을 넣는다(예: `firewall-cmd --add-rich-rule='rule family=ipv4 source
> address=<AP서버IP>/32 port port=7687 protocol=tcp accept'` — 5432 · 59020 도 같이).
> 넣은 뒤 **AP 가 아닌 PC 에서 닿지 않는 것**을 한 번 확인한다.

> **authority-init 은 한 번 돌고 끝나는 게 정상이다** (`Exited (0)`). 권한 서버의 DB 역할,
> 표, **최초 관리자**, 승인 정책을 만든다. 다시 띄워도 안전하다(이미 있으면 그대로 둔다).

## 9. SWP 첫 연동 — 한 번만

SWP 가 돌려주는 사용자 정보(콤마 구분)의 **칸 순서**가 현장마다 다를 수 있다. 틀리면 오류 없이
**다른 사번으로 로그인된다.** 첫 로그인 직후 한 번 확인한다.

한 사람이 로그인한 뒤 (분할이면 **DB 서버**에서 `-f docker-compose.split.db.yml` 을 붙인다):

```bash
docker compose logs authority | grep 'auth.sso.validated' | tail -3
```

찍힌 `empno` · `username` 이 **로그인한 그 사람의 사번·ID** 인지 본다. 앱 화면 오른쪽 위의
이름·메일도 본다. 기본 칸 순서는 `0=ID · 1=사번 · 8=이름 · 9=메일 · 4=부서` 다.

```text
맞다     끝. 할 일 없음
다르다   개발 쪽에 알린다 — SWP_IDX_* 는 yml 의 고정값이라 개발 쪽이 고쳐 판을 낸다
         그 전까지는 다른 사람이 로그인하지 않게 한다(사번이 엇갈려 권한이 섞인다)
```

> ⓘ 예전 관리자 가이드의 `SWP_SSO_LOG_RAW=1`(원문 찍기)은 **코드에 구현돼 있지 않다** — 주석에만
> 있는 이름이었다. 그래서 이 판에서는 위의 로그로 확인한다.

## 10. 운영

| 하고 싶은 것 | 명령 |
|---|---|
| 멈추기 (데이터 그대로) | `docker compose stop` |
| 다시 켜기 | `docker compose up -d --wait` |
| 로그 | `docker compose logs -f --tail 100 <서비스>` |
| 새 판으로 올리기 | **§10-1 의 여섯 줄** — 같은 폴더에 다시 묶지 않는다 |
| 백업 | 볼륨 `robo-posco-web_graph_data` (팀 데이터 전부) |

> `graph_data` 볼륨이 지워지면 **모든 프로젝트·분석이 사라지고 되돌릴 수 없다.**

### 10-1. 새 판으로 올리기 — **새 폴더에 묶는다**

```bash
cd ~/robo-architect && git pull                       # ① 새 판 받기
bash deploy/posco-web/bundle.sh ~/robo-posco-web-2    # ② **새** 폴더에 묶기

> ⚠ **인터넷이 없는 서버는 ⑥ 의 `docker compose pull` 이 실패한다.** 그 자리는 새 묶음의
> 이미지를 **먼저 넣는 것**으로 바꾼다 — `docker load -i images.tar`(또는 Portainer Import)
> 를 한 뒤 `docker compose up -d --wait` 만 친다.

```text
왜 **새 폴더**인가   `bundle.sh` 는 비어 있지 않은 폴더를 거부한다("비어 있지 않다") —
                    쓰던 묶음을 덮어써 .env 를 날리지 않으려고 그렇게 만들었다.
                    (2026-11-11 까지 이 가이드는 "같은 폴더에 bundle.sh 다시" 로 적혀
                     있었다. 그대로 하면 ②에서 멈춘다 — 실제로 돌려서 확인했다)
데이터는 따라온다    볼륨 이름은 폴더가 아니라 yml 의 `name: robo-posco-web` 에서 나온다
                    (`robo-posco-web_graph_data`). 폴더를 바꿔도 같은 볼륨을 다시 붙는다
옛 폴더는 남긴다    되돌릴 길이 거기다(§10-2). 한 판 지나고 지운다
```

```bash

```text

## 11. 문제가 생기면

| 증상 | 원인 | 고치기 |
|---|---|---|
| `check.sh` 가 `… 를 아직 안 채웠다` | `.env` 에 `CHANGE_ME` 가 남았다 | §4 |
| SWP 로그인 뒤 "허용되지 않은 callbackUrl" | `ROBO_PUBLIC_URL` 이 브라우저 주소와 다르다 | 주소·포트를 똑같이 적고 `docker compose up -d authority` |
| 로그인은 되는데 프로젝트를 못 연다 | `AUTH_ROLE_SECRET` 이 바뀌었다 | 처음 값으로 되돌린다(바꾸면 안 되는 값이다) |
| graph-db·fabric 이 인증 실패로 unhealthy | 볼륨을 만든 뒤 `ROBO_GRAPH_PASSWORD` 를 바꿨다 | 처음 값으로 되돌린다 |
| authority 가 재시작을 반복 | `docker compose logs authority-init` 에 오류가 있다 | 그 메시지대로 `.env` 를 고치고 다시 `up` |
| `port is already allocated` | msa-ez 등이 포트를 쓴다 | `ROBO_WEB_PORT` · `ROBO_DB_*_PORT` 변경 |
| podman 에서 authority 가 안 뜬다 | compose 구현이 `service_completed_successfully` 를 모른다 | `podman compose version` 이 docker-compose v2 를 쓰는지 확인 |
| 브라우저에 빈 화면 | web 이 API 를 못 찾는다 | `docker compose ps` 로 architect-api 가 healthy 인지 |

## 12. 로컬 시험 — SWP 없이 내 PC 에서 눌러 보기

SWP 는 **사내망에서만** 응답하고, 서버 판의 권한 서버는 시험 로그인을 **일부러** 막는다. 그래서
사내망 밖의 PC 에서는 로그인할 길이 없다. 그때는 **로컬 시험용 파일**을 하나 더 붙여 띄운다.

```bash
docker compose -f docker-compose.yml -f docker-compose.local-test.yml up -d --wait
```

PowerShell 이면 한 줄 그대로 친다(이 명령은 PowerShell 에서도 돈다).

```text
브라우저   http://127.0.0.1:8080  → 로그인 화면 아래 "개발용 로그인"
관리자     admin / admin       사번 = .env 의 ROBO_ADMIN_EMPNO → 이미 승인된 관리자
두 번째    user2 / user2       "승인 대기"로 들어온다 → 관리자가 승인 (공유 시험용)
```

무엇이 달라지나:

```text
✔ 로그인    권한 서버 대신 architect-api 가 직접 한다(시험 로그인 켬)
✔ 그대로    로그인 강제 · 사용자별 DB 계정 · 프로젝트 만들기·공유·승인 — 실제와 같은 길
✔ 막아 둔 것 web 을 127.0.0.1 에만 연다 → 다른 PC 에서는 이 시험 로그인에 닿지 못한다
```

> ⚠ **사내 서버에서는 이 파일을 붙이지 않는다.** `.env` 의 스위치가 아니라 **파일**로 둔 이유가
> 그것이다 — `-f` 로 일부러 붙여야만 효과가 있어 실수로 로그인이 꺼질 일이 없다.
> 관리자 비밀번호를 바꾸려면 `.env` 에 `ROBO_TEST_LOGIN_PASSWORD=…` 를 한 줄 더한다.

로컬 시험에서는 AI 값(`ROBO_AI_*`)이 가짜여도 화면·로그인·프로젝트는 된다. 분석·생성처럼
AI 를 부르는 단계만 그때 실패한다.

내릴 때(데이터는 남는다):

```bash
docker compose -f docker-compose.yml -f docker-compose.local-test.yml down
```

## 13. 알아 둘 것

- **lite 와는 무관하다.** lite 는 다른 가지·다른 이미지(`robo-architect-lite-*`)이고, compose
  프로젝트 이름도 다르다(`robo-architect-desktop` / 이 판은 `robo-posco-web`).
- **묶음 폴더에서 띄우는 것을 권한다**(`bundle.sh` 로 만든 곳). 저장소 폴더에서 띄워도 이제는
  같게 돈다 — 그렇지 않던 원인이던 `pdf2bpmn/facade.py` 바인드 마운트가 없어졌다(아래).
- **문서→BPMN(pdf2bpmn) 서비스는 빼 두었다**(2026-11-11). 그 1단계는 저장소 안의 추출기가
  하고, PDF 글자 뽑기는 업로드할 때 따로 한다 — 기능이 사라진 것이 아니다. 이미지가
  열둘에서 **열하나**로 줄었다. 자세한 것은 묶음의 `README.md` 의 pdf2bpmn 절에 있다.
- **Claude Code 터미널(Code 탭)은 이 판에 없다.** 그 터미널은 보는 사람 PC 의 CLI 를 띄우는
  것이라 서버에서는 뜻이 없다. 코드 생성·템플릿 기능은 그대로 쓴다.
- **문서 내보내기**는 브라우저에서 `.docx` 파일로 내려받아진다.
- 이미지 열한 장은 `ghcr.io/uengine-oss/robo-posco-*` 로 **공개**돼 있다. 비밀은 이미지에 없고
  `.env` 에만 있다.
- 설계 결정과 근거는 묶음의 `README.md` 에 있다.
